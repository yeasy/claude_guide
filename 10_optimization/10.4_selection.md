## 10.4 模型选择与路由策略：Model Routing 与 Cascading

在 AI 工程中，“One Model Fits All”并不成立。要在质量、成本和延迟之间取得最优平衡，需要构建 **Model Router（模型路由器）**。

### 10.4.1 模型分层

路由策略应先按模型家族分层，而不是绑定某个短期型号：

| Tier | 模型家族 | 擅长 | 成本 | 延迟 |
| :--- | :--- | :--- | :--- | :--- |
| **S-Tier** | **Opus 类** | 复杂推理、难例处理、深度规划 | $$$ | 慢 |
| **A-Tier** | **Sonnet 类** | 编程、数据分析、通用生产任务 | $$ | 中 |
| **B-Tier** | **Haiku 类** | 简单分类、提取、翻译、聊天 | ¢ | 快 |

这样即使未来版本号更新，路由策略也不必重写。

### 10.4.2 静态路由

最简单的路由是按任务类型做规则分发：

```python
def route_request(task_type, prompt):
    if task_type == "coding":
        return call_sonnet_family(prompt)
    elif task_type == "summarization":
        return call_haiku_family(prompt)
    elif task_type == "creative_writing":
        return call_opus_family(prompt)
```

静态路由实现简单，可预测性强，但对边界样本不够灵活，容易把本可由便宜模型处理的请求错误升级。

### 10.4.3 动态路由

动态路由先由轻量 Router 判断请求的复杂度，再决定是否升级模型。

**Router Prompt**：
> “评估以下用户请求的复杂度（Level 1-5）。
> Level 1-2：日常问候、简单事实查询 -> Route to Haiku family
> Level 3-4：编程、逻辑推理、文档分析 -> Route to Sonnet family
> Level 5：极端复杂的规划、证明或高风险难例 -> Route to Opus family”

动态路由的要求是：Router 的判断成本足够低，误判代价可控，升级路径可观测、可复盘。

### 10.4.4 级联降级：Cascading / Fallback

级联降级兼顾成本与兜底：默认先尝试便宜模型，失败后再升级。

**Coding Task Workflow**：
1.  **Attempt 1**：先用 **Haiku 类模型** 尝试写代码。
2.  **Verify**：运行单元测试或静态检查。
    *   如果通过 -> Return。
    *   如果失败 -> 进入下一步。
3.  **Attempt 2**：把失败代码、报错信息和约束条件一起交给 **Sonnet 类模型**。
4.  **Fix**：由更强模型修复，再进入下一轮验证。

这种策略的价值不在某个固定的节省百分比，而在于把简单流量拦在便宜模型上，只让复杂样本触发升级，并由验证环节而非主观感觉决定是否升级。

收益测算应使用自己的业务数据：

```text
综合成本
= 低成本模型命中率 × 低成本路径成本
+ 升级率 × 升级后总成本
```

### 10.4.5 A/B Testing 与 Evals

判断路由策略是否有效，需要建立 **Evals（评估体系）**：

*   构建一组覆盖真实业务分布的 Golden Dataset。
*   分别让不同模型家族执行同一批任务。
*   记录质量、成本、时延、升级率和失败率。
*   画出 **Pareto Frontier（帕累托前沿）**，找到“质量下降可接受、成本下降明显”的甜蜜点。

评估路由策略时，至少要看 5 个指标：

*   首次成功率
*   综合成本
*   P95 延迟
*   升级率
*   人工接管率
