## 本章小结

本章介绍了大型语言模型（LLM）从“被动问答”走向“主动代理”的关键一步。借助工具使用（Tool Use），Claude 能够获取外部信息、操作数据和执行任务，不再局限于预训练知识。

### 核心知识点回顾

#### 工具的本质

工具是 Claude **逻辑推理能力的延伸**。
*   **客户端工具**：开发者掌握控制权，Claude 负责意图识别和参数生成。
*   **托管工具**：Anthropic 提供的开箱即用能力（如联网搜索）。3.1 节用“托管”而非“服务端”，以免与开发者自己部署在服务器上的客户端工具混淆。

#### 工具定义

*   **Description is Prompt**：工具描述是系统提示词的一部分，决定了调用的准确率。
*   **JSON Schema**：精确的参数类型定义（Enum, Required, Format）是防止参数幻觉的第一道防线。

#### 请-算-行-馈

Agent 运行的生命周期分为四步：
1.  **Stop Reason**: 识别 `tool_use` 信号。
2.  **Execution**: 并行或串行执行业务逻辑。
3.  **Result**: 构造包含 Text、Image 或 Document 的 `tool_result`。
4.  **History**: 维护完整的对话链条。

#### 复杂编排

*   **并行模式**：利用 asyncio 降低多工具调用的延迟。
*   **人机协作 (HITL)**：在关键操作前引入人工审批，确保安全。
*   **状态管理**：区分哪些状态属于 Context，哪些属于外部数据库。

#### 高级特性

*   **程序化工具调用**：让 Claude 写代码而非逐次输出 JSON，大幅提升处理复杂逻辑和大量数据的效率。
*   **工具搜索**：通过“按需加载”机制，解决 Token 限制与大规模工具库之间的矛盾，使 Agent 可以挂载成千上万个工具。

### 开发者自检清单

开始构建 Agent 之前，逐项自检：
- [ ] **命名规范**：我的工具名称是否清晰，且不易与现有工具混淆？
- [ ] **描述完整**：description 是否包含了“何时使用”、“参数格式”以及“返回什么”？
- [ ] **错误处理**：当 API 失败时，我是否返回了 `is_error: true` 且带有指导性的错误信息？
- [ ] **Token 预算**：我的工具定义是否过于冗长？是否需要使用工具搜索？
- [ ] **安全性**：是否为了方便而赋予了过大的权限（如 `DROP TABLE`）？是否有人工确认环节？
