## 1.2 Claude 模型家族全景

### 1.2.1 三个核心模型系列与前沿档位

Anthropic 将 Claude 划分为不同定位的系列，而不是用单一模型覆盖全部场景。这种分层让开发者可以在 **智能水平（Intelligence）**、**响应速度（Speed）** 和 **使用成本（Cost）** 之间灵活取舍。

最常用的三个系列是：**Opus（史诗/巨作）**、**Sonnet（十四行诗）** 和 **Haiku（俳句）**；在更高推理上限需求下，Anthropic 另提供 **Fable** 前沿系列（受限安全研究线 **Mythos** 非普遍可用，仅向 Project Glasswing 获批客户或通过官方验证项目的组织开放）。

#### Claude Opus：史诗

*   **定位**：旗舰通用档，官方“不确定选哪个时的起点”。
*   **特点**：深度推理与复杂工程能力突出，适合复杂代码库分析、系统架构设计、科研写作和长链路 Agent 任务。
*   **适用场景**：需要高质量复杂推理，且预算与响应时间相对充裕的场景。
*   **形象比喻**：一位学识渊博的大学教授。

#### Claude Sonnet：十四行诗

*   **定位**：平衡主力档，企业与日常开发首选。
*   **特点**：智能水平接近 Opus，响应更快、单价更低，是日常开发和多数生产工作流的高性价比默认选择。
*   **适用场景**：代码生成与调试、RAG、数据提取、常规多步 Agent 工作流。
*   **形象比喻**：一位经验丰富的高级工程师。

#### Claude Haiku：俳句

*   **定位**：轻量高速档，低延迟高并发优先。
*   **特点**：体积小、吞吐高，当前型号 Claude Haiku 5.5 提供 1M 上下文与 128K 最大输出，专为大批量、实时场景设计。
*   **适用场景**：即时聊天、内容审核、海量文档摘要、复杂系统中的意图路由器或分类器。
*   **形象比喻**：一位动作敏捷的实习生助理。

#### Claude Fable 与 Mythos：前沿上限与受限研究线

*   **Claude Fable**：面向需要最高推理上限与超长周期智能体任务的公开可用（GA）前沿系列。初代 Fable 5 已于 2026-07-01 恢复全球访问，当前主力为 **Claude Fable 5.2**（`claude-fable-5-2`）。
*   **Claude Mythos**：面向前沿网络安全与验证研究的受限系列，**非普遍可用**，Mythos 5 / 5.1 仅向 Project Glasswing 获批客户有限开放（无自助注册），Mythos 5.2 仅向通过 Anthropic 验证项目的组织开放。

### 1.2.2 当前主力阵容与演进脉络

初次接触 Claude 时，先记住官方当前推荐的四款主力型号即可：

| 模型 | API 模型 ID | 定位 | 上下文 / 最大输出 | 核心特点 |
| :--- | :--- | :--- | :--- | :--- |
| **Claude Fable 5.2** | `claude-fable-5-2` | 前沿推理上限 | 1M / 128K | Adaptive Thinking 常开，适合极高复杂度长程智能体任务 |
| **Claude Opus 5.5** | `claude-opus-5-5` | 旗舰通用起点 | 1M / 128K | 官方默认起点，Adaptive Thinking 常开，默认 `effort` 为 `medium` |
| **Claude Sonnet 5.5** | `claude-sonnet-5-5` | 均衡主力 | 1M / 128K | 编码与日常 Agent 性价比主力，Adaptive Thinking 默认开启 |
| **Claude Haiku 5.5** | `claude-haiku-5-5` | 高速低成本 | 1M / 128K | 大批量低延迟任务与路由分类首选，支持 Adaptive Thinking |

从 2023 年至今，Claude 的演进可以概括为五个关键里程碑：

1.  **Claude 1 与 2（2023）**：率先将上下文窗口推进到 100K token，开启长文档处理时代。
2.  **Claude 3 / 3.5 / 3.7（2024–2025 初）**：确立 Opus / Sonnet / Haiku 矩阵，陆续引入视觉输入、Artifacts、Computer Use，并在 3.7 首次推出 Extended Thinking 混合推理。
3.  **Claude 4 系列（2025–2026 上半）**：将上下文窗口扩展至 1M token，逐步从手动 Extended Thinking 过渡到 Adaptive Thinking，显著增强 Agentic 编码能力。
4.  **Claude 5 代（2026 年中）**：引入 Fable / Mythos 前沿线，推出 `claude-sonnet-5` 与 `claude-opus-5`（两者现已随 5.5 发布转入 Legacy models，仍可调用）。
5.  **Claude 5.x 当前阵容（2026 下半）**：Fable 5.2、Opus 5.5、Sonnet 5.5 与 Haiku 5.5 全面统一 1M 上下文与 Adaptive Thinking 默认架构，并进一步下调单位价格。

### 1.2.4 新兴能力维度：Extended Thinking 与 Adaptive Thinking

在传统的“智能-速度-成本”三角之外，Claude 引入了新的维度：**思考时间（Thinking）**。
它允许模型在输出结果前先进行内部推演，从而在复杂逻辑、数学证明和大型重构任务上显著提升一次通过率，代价是更多的延迟与输出 Token。

理解这一能力只需要先抓住一个演变方向：

*   **Extended Thinking（扩展思考，旧路径）**：早期需要开发者手动配置固定 `budget_tokens`，仅保留在部分旧版模型（如 Haiku 4.5、4.6 兼容路径）中。
*   **Adaptive Thinking（自适应思考，当前主路径）**：当前主力型号（Fable 5.2、Opus 5.5、Sonnet 5.5、Haiku 5.5）默认开启自适应思考，由模型按任务难度动态分配思考深度，开发者通过 `effort` 参数控制推理强度。

不同型号对关闭思考和兼容参数的精确限制，请参阅 [8.4 扩展思考](../08_agent/8.4_extended_thinking.md) 与 [附录 H：版本演进与迁移历史](../12_appendix/12.8_version_migration.md)。

### 1.2.5 如何选择？

下一节“模型选择”会详细讨论，这里先给出一条简单法则：

> **“Default to Sonnet, optimize with Haiku, escalate to Opus.”**
> **“默认用 Sonnet，用 Haiku 优化成本，遇难事找 Opus。”**

1.  **开发阶段**：直接使用 **Sonnet**。它响应快、智能足够，开发者可以专注于业务逻辑而非过早调优。
2.  **上线前优化**：
    *   检查 Prompt 历史。如果发现大量任务只是简单的“提取 JSON”或“分类”，尝试切换到 **Haiku** 并微调 Prompt。节省幅度取决于输入/输出比例和缓存命中率，不能把“90%”当作通用承诺。
    *   如果发现某些复杂的长逻辑链推理（Chain of Thought）经常出错，将该特定步骤的模型切换为 **Opus**（或更高上限的 **Fable**）。
3.  **混合编排**：成熟的 Agent 系统往往混合使用多个模型。例如，用 Haiku 快速判断用户意图，再按复杂度分发给 Sonnet 或 Opus 处理。

### 1.2.6 演进趋势

从 Claude 3 到 5.x，有三个明显的趋势：

1.  **能力门槛持续下移**：轻量档和平衡档不断吸收上一代旗舰能力，常规开发不再需要动辄调用最贵型号。
2.  **单位价格持续下降**：旗舰与主力档单价显著低于早期版本，叠加提示缓存与批处理后，生产成本进一步可控。
3.  **上下文与自主思考成为标配**：1M 上下文窗口和 Adaptive Thinking 逐步覆盖主力产品线，推动应用从单轮问答转向长周期 Agent 工作流。
