## 8.1 Claude Agent 概述

2023 年被称为 “Year of the Chatbot”（聊天机器人元年），而 2025 年则是 “Year of the Agent”（智能体元年）。
这一转变的原因是，人们不再满足于让 AI 只会 **说话**，而是要求它能够 **做事**。

> 💡 关于智能体的完整介绍，请参阅《智能体 AI 权威指南》。

### 8.1.1 Agent vs. Chatbot：核心区别

在众多 LLM 中，Claude 被公认为最适合做 Agent 的模型（“The Agentic Model”），原因在于以下三项优势：

#### 1. Tool Use 准确率最高

Claude 在函数调用和工具使用评测中长期保持第一梯队表现，具体排名应以 [Berkeley Function Calling Leaderboard](https://gorilla.cs.berkeley.edu/leaderboard.html) 等评测的当前快照为准。对 Agent 来说，工具调用质量直接决定成败：一个错误的 API 调用就可能导致整个任务失败。

#### 2. 超长 Context 支持（最高 1M）

Agent 在运行过程中会产生大量的日志、中间状态和执行历史。Claude 的 1M context 能够容纳更长的执行轨迹，减少“灾难性遗忘”，使 Claude 在复杂的多步任务中也能准确记住早期信息。

#### 3. Constitutional AI 内置安全机制

[Constitutional AI](../11_safety/11.1_cai.md) 使得 Claude 在面对危险指令（如 “删除所有数据库”）时，拥有内置的道德刹车。但它只能降低风险，不能替代权限隔离、人机确认、审计和回滚。对于拥有执行权的 Agent，这些外部护栏 **必不可少**，因为失控的 Agent 可能造成真实世界的损害。

### 8.1.2 Agent 的典型流程

一个 Claude Agent 的执行循环如下：

```text
用户目标 → Claude 理解意图 → 规划任务拆解
   ↓
调用 MCP 工具 (如文件访问、API 调用、代码执行)
   ↓
观察工具返回结果
   ↓
根据结果反思是否达成目标 → 决定是否继续或纠正方向
   ↓
重复直至任务完成
```

Claude 通过 [MCP (Model Context Protocol)](../04_mcp/README.md) 访问各种工具。

### 8.1.3 Claude Agent 的自动化等级

根据人类干预的程度，Agent 可以分为四个等级：

| 等级 | 名称 | 人类角色 | 典型场景 |
|------|------|--------|--------|
| **L1** | Copilot | 指挥每一步 | “帮我重构这个函数” |
| **L2** | Router | 定义意图，AI 调度工具 | “帮我查天气” → 自动选择 Weather API |
| **L3** | Generalist | AI 自主规划和重试 | “帮我写一个贪吃蛇游戏并运行” |
| **L4** | Autonomous | 无需干预，自主运行 | “每周五自动爬取竞品价格，生成报告” |

本章重点探讨 **L3 和 L4 级别**：AI 具有完整的规划、决策和自我修正能力。

### 8.1.4 构建 Claude Agent 的关键要点

构建 Claude Agent 首先依赖 **Tool Use 的可靠性**：工具调用一旦出错，后续步骤都会失败。其次是 **Long Context 管理**：执行历史不断增长，多步任务需要保持上下文的有效性。最后，**Constitutional AI 安全约束**能降低有害操作风险，但生产级 Agent 仍必须配合[安全护栏](../11_safety/11.2_guardrail.md)、权限隔离、HITL、审计和回滚。
