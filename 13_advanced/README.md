# 第十三章 进阶能力：Claude 前沿特性与上下文工程

> **关于章号**：本书正文为第一至第十一章，本进阶章沿用“第十三章”编号；中间的“第十二”位置对应**附录**部分（API 参考、FAQ、术语表、定价、竞品对比、快变事实核验表等，见侧边目录“附录”）。因此目录中第十一章之后直接到本章属于编号设计，并非缺漏。

本章内容分为已确认信息和合理推测两类：前者以最新的官方文档为准，后者基于行业趋势。

## 章节概述

前面各章介绍了 Claude 的现有能力、工具生态和应用模式。本章介绍 Claude 的进阶能力，包括最新模型特性、长对话管理和上下文工程实践，帮助读者从基础使用走向系统级应用。

> **与第二章的关系**：第二章介绍的“提示工程”聚焦于单次交互中的措辞和指令优化技巧，是与 Claude 协作的基本功。本章在此基础上进一步拓展：13.1 节帮助你了解最新模型的能力边界与选型策略，13.2 节讲解长对话和大上下文窗口的管理方法，13.3 节从系统架构视角介绍“上下文工程”，即如何动态组织提供给模型的全部信息（RAG、工具输出、对话历史等）。第二章讲“怎么说”，本章讲“给什么”和“如何管理”。

本章分为四个相互关联的部分：

### 13.1 Claude 4.x 现状与 Claude 5 展望

本部分包括两类内容：

**已确认特性**（基于 Anthropic 官方文档）：
- Claude 4.5/4.6/4.7/4.8 系列的能力全景
- 官方文档和发布说明中明确写出的能力边界
- Anthropic 的已确认技术投资方向
- 模型选择的决策框架
- 成本-性能的权衡指南

**展望与推测**（基于行业趋势，明确标注为非官方预测）：
- Claude 5 的可能能力方向
- 发布时应核对的模型、接口、价格和安全边界

**核心观点**：区分已确认事实与合理推测，既能准确理解 Claude 的现有能力，也能为可能的变化做好准备。

### 13.2 长对话管理实战指南

长对话管理是一种应用层工程模式，而非独立的官方产品名。本部分讨论如何组合上下文窗口、提示缓存、摘要、检索和记忆能力来支撑长期项目：

- 长对话管理的核心原理和工作机制
- 长对话的生命周期管理
- 1M Token 级长上下文能力的最优使用
- 对话分叉与多线程技术
- 实际使用技巧和成本优化

**核心观点**：长对话管理不是“无限上下文”，而是把完整历史保存在应用侧，并把当前任务所需证据可靠地放回本次请求。

### 13.3 Context Engineering 概览

Context Engineering（上下文工程）正在取代 Prompt Engineering，成为与 LLM 交互的主导方法。本部分包括：

- 为什么上下文工程正在取代提示词工程
- 四大核心策略：写入、选择、压缩、隔离
- Claude 中的上下文工程实践
- RAG 和 MCP 在上下文工程中的作用
- 实际案例和最佳实践

**核心观点**：关键在于给模型什么，而不只是如何问。充分且组织良好的上下文，能够弥补甚至超过提示词措辞优化的作用。

### 13.4 模型内部可解释性：Anthropic 的解释性研究进展

本部分介绍 Anthropic 最新的解释性研究，讨论模型内部如何运作，以及 Claude 何时会采取不道德行为或表现出“挫折感”，内容包括：

- 情感向量：神经网络内的功能性情感表征
- 绝望向量与不道德行为的因果关系
- 人格理论：为什么 Claude 表现得“像人”
- 解释性研究的实践应用

**核心观点**：理解模型内部的神经表征机制，有助于预测、诊断和引导模型行为，构建更安全、更可靠的 AI 系统。

## 关键概念

### Claude 4.x 与 Claude 5

- **4.5**：稳定版本，提供平衡的性价比
- **4.6**：性能升级版本，推理能力显著提升，1M 上下文的可用性和计费按官方文档核验
- **4.7**：上一代旗舰，在软件工程和复杂推理上表现优异
- **4.8**：发布时的 Opus 档旗舰（2026-05-28），在 4.7 基础上改进长跨度 Agentic 编码、effort 校准与工具触发；2026-07-24 起由 Opus 5 接替，已转入官方 Legacy models
- **5**：**Claude Fable 5**（$10/$50、1M 上下文、128K 输出、Adaptive Thinking 常开）在 6 月暂停后已于 2026-07-01 恢复全球访问；**Claude Mythos 5** 非普遍可用，仅向 Project Glasswing 获批客户有限开放，采用邀请制且无自助注册；**Claude Sonnet 5** 已发布（见 13.1 的迁移清单）

### 上下文窗口的演进

- **当前**：1M token 级长上下文能力（具体可用性按平台文档）
- **近期**：在更稳定的长上下文工程与压缩机制上继续演进
- **长期**：更高效地使用长上下文、缓存、压缩和外部记忆，而不是假设存在真正无限的上下文

### 新范式的核心转变

从 **“如何问”** 转向 **“给什么”**

| 维度 | 旧范式（提示词工程） | 新范式（上下文工程） |
|-----|------------------|------------------|
| 优化焦点 | 指令的表述 | 提供的信息 |
| 关键资源 | 优化的语言 | 高质量的数据 |
| 扩展方式 | 手动调整提示 | 自动选择上下文 |
| 成本驱动 | 迭代时间 | token 数量 |
