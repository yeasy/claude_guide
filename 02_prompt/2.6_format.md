## 2.6 输出格式控制

Prompt Engineering 的目标往往是获得“可用”的答案，而不只是“正确”的答案。
开发者最常遇到的问题是 Claude 先回复一句 *“Here is the JSON you requested...”*，或者在 JSON 里加注释导致 `JSON.parse` 报错。

本节介绍获得 **干净的机器可读输出 (Clean Machine-Readable Output)** 的几种方法。

### 2.6.1 核心技术：Prefill

> **兼容性提示**：自 Claude 4.6 系列及 Mythos Preview 起，所有更新的模型（含 Fable 5.2、Opus 5.5、Sonnet 5.5、Haiku 5.5、Fable 5.1、Opus 5、Sonnet 5、Opus 4.6/4.7/4.8、作为迁移基线的 Sonnet 4.6、Fable 5 与 Mythos 5）均**不再支持**对最后一条 assistant 消息做 Prefill，使用时会返回 400 错误；在对话中段插入 assistant 消息不受影响。对于这些新模型，请使用 Structured Outputs（见 2.6.3 节）或系统提示词来控制输出格式。以下内容仅适用于 Claude Sonnet 4.5 / 3.5 等仍支持 Prefill 的模型。

这是 Claude 早期模型特有的格式控制技术。
在通用的 Chat Completions API（如 OpenAI）中，`Assistant` 的消息通常由模型生成；在 Claude 的 Messages API 中，**可以手动代替 Assistant 写出“第一句话”**。

模型只能从这句话接着往下写。

#### 强制 JSON 输出

不要只在 System Prompt 里提要求，直接用 `{` 作为回复的开头。

**API Payload:**
```jsonc
{
  "messages": [
    {"role": "user", "content": "请分析这段文本的情感，输出 JSON。文本：..."},
    {"role": "assistant", "content": "{"} // <--- 关键！
  ]
}
```

**Claude 的反应**：
它必须从 `{` 后面接着写。由于 `{` 已经输出，它 **不可能** 再说 “好的，这是你的分析：”，只能继续生成 `"sentiment": "positive"...`。

**后端拼接**：
```javascript
async function main() {
  const response = await callClaude({ messages });
  const fullJson = "{" + response.content[0].text; // 记得把预填充的字符拼回去！
  return JSON.parse(fullJson);
}
```

#### 强制 XML 输出

同理，预填充根标签（如 `<analysis>`）。

```python
messages=[
    {"role": "user", "content": "..."},
    {"role": "assistant", "content": "<analysis>"}
]
```

#### 引导思维方向

Prefill 还能控制内容方向。

*   *User*: “给我写个故事。”
*   *Assistant (Prefill)*: “这是一个漆黑风暴的夜晚，”
*   *Claude*: “侦探史密斯压低了帽檐...”

### 2.6.2 移除“废话”

如果无法使用 API 的 Prefill 功能（例如使用某些第三方客户端），可以通过 Prompt 措辞减少多余文字。

#### 负面约束法

```xml
<format_instructions>
只输出 JSON。
不要输出 Markdown 代码块标记（如 ```json）。
不要输出任何解释性文字。
如果输出包含 JSON 以外的任何字符，世界就会爆炸。
</format_instructions>
```

#### 示例示范法

通过 Few-Shot 示范不附加任何说明的输出。

```xml
<example>
    <input>提取姓名</input>
    <output>{"name": "John"}</output>
</example>
```

### 2.6.3 标准格式详解

#### JSON Mode

API 集成首选 JSON，建议定义 Schema：

```xml
<output_schema>
{
  "type": "object",
  "properties": {
    "summary": {"type": "string"},
    "tags": {"type": "array", "items": {"type": "string"}},
    "score": {"type": "number", "minimum": 1, "maximum": 10}
  },
  "required": ["summary", "tags", "score"]
}
</output_schema>
```
Claude 很擅长遵循这种类 JSON Schema 的定义。

#### Structured Outputs：原生结构化输出

除了通过 Prompt 控制外，Claude API 支持两类结构化输出能力：

*   **JSON outputs**：通过 `output_config.format` 指定 JSON Schema，让最终响应按 schema 返回。
*   **Strict tool use**：通过工具定义中的 `input_schema` 与 `strict: true` 保证工具调用参数符合 schema。

纯数据抽取或结构化报告优先用 `output_config.format`；需要调用业务函数时再使用 strict tool use。

#### CSV

适合生成大量数据供 Excel 分析。

```text
请生成 50 条模拟用户数据。格式：id,name,email,role。
不要包含表头。每行一条。
```

#### Markdown 表格

最适合人类阅读的结构化格式。

```text
| ID | Name | Status |
|---|---|---|
...
```

### 2.6.4 长度控制

Claude 的回答有时过长，可用以下技巧控制长度。

| 目标 | Prompt 技巧 |
| :--- | :--- |
| **极简** | “Be extremely concise. No filler words.”（极度简洁，无废话）|
| **字数限制** | “Strictly under 50 words.”（严格控制在 50 字以内，注意 token vs word 差异）|
| **段落限制** | “Answer in exactly 3 bullet points.”（确切使用 3 个要点）|
| **针对性** | “Only answer the 'What', ignore the 'Why'.”（只答是什么，不答为什么）|

### 2.6.5 Stop Sequences：停止序列

这是 API 层面最直接的控制手段：指定某个字符序列，一旦生成该序列就立即停止。

**场景**：只希望 Claude 填空。
Prompt: `Q: 1+1=? A:`
Stop Sequence: `\n\nQ:`（下一道题的开头）

Claude 生成 `2` 后会顺着格式继续编下一道题，一旦生成 `\n\nQ:`，API 立即截断，于是得到干净的 `2`。

> 注意：stop sequence 不能只含空白字符。单独的 `\n` 会被 API 以 `invalid_request_error` 拒绝（提示 `each stop sequence must contain non-whitespace`），所以序列里要带上 `Q:`、`###` 这类非空白字符。
